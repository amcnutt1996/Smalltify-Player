# Decisions

How each choice was made: **User** means you decided it in chat, **Orch** means the orchestrator decided, and **Agent** means a build agent decided it and the orchestrator accepted. Every decision after you stepped away is marked *(autonomous)*.

| # | Decision | By | Why |
|---|---|---|---|
| 1 | GUI: raylib 5.5 in event-waiting mode, with no raygui | User | One C library on every OS. With event waiting the window sleeps until there is input; background threads wake it with `glfwPostEmptyEvent()`. |
| 2 | ~~librespot ships next to the binary~~ → **superseded by #18**. The engine lives in `<app>/soloist/` inside the portable folder | User | You wanted no files written outside the app folder. |
| 3 | All runtime data in `<app>/data/`; nothing in the cache dir, AppData, $HOME or /tmp; album art kept in memory only | User | Portability; no leftovers on the machine. |
| 4 | ~~librespot 0.8.0 built with cargo~~ → **removed by #18** | User + Agent | It worked, but Spotify refuses its audio keys on your account (#9). |
| 5 | Portable C11 with POSIX + Win32 in one `platform.c`; verified only on macOS arm64 | User | Only a Mac is available here. The Win32 code has not been compiled. |
| 6 | Sign-in: Authorization Code + **PKCE**. `SPOTIFY_CLIENT_SECRET` is ignored and never read | Orch | A secret in a folder you hand out isn't secret. Spotify recommends PKCE for desktop apps. |
| 7 | `dist/.env` is seeded from `.env.example` plus **only** the `SPOTIFY_CLIENT_ID=` line of the repo `.env` | Orch | Keeps the secret out of build output. |
| 8 | ~~Two sign-ins (app + librespot)~~ → **superseded by #18**: one app sign-in, plus a Soloist key and a one-time pairing | Orch | Since Aug 2026 Spotify's login5 rejects third-party tokens for librespot. |
| 9 | ~~Hybrid librespot + other devices~~ → **superseded by #18**. The device picker stays as a feature | User | Your account got `error audio key 0 1`, a permanent Spotify refusal with no client-side fix (librespot#1649). |
| 10 | Polling: the UI ticks at 1 Hz from local interpolation; the Web API is fetched every 5 s while playing, at the predicted end of each track, and immediately after your own commands. Idle and minimized states poll every 5 s; network errors and 429s back off 2→30 s (other errors keep the 5 s cadence); "background" means minimized only, so a visible unfocused window keeps its 1 Hz tick; no redraw when nothing changed | Orch (+ PerfReviewer, *autonomous*) | Battery life. This cut requests from 60/min to about 12/min while playing. A pause made on another device shows up within 5 s. |
| 11 | One curl handle per thread, reused: keep-alive, reused TLS sessions, HTTP/2, gzip | Orch | No TLS handshake per poll. |
| 12 | GUI commands go through one worker thread with a single-slot mailbox (latest command wins) and optimistic UI | Agent | The UI never blocks; rapid clicks collapse into one command. |
| 13 | `transfer` keeps the current play/pause state (`play=false`); the GUI picker transfers with `play=true` | Orch *(autonomous)* | The CLI matches Spotify's default behaviour. In the GUI, choosing a device means you want to hear it. |
| 14 | Tests: plain `assert` + ctest, offline fixtures only; `-UNDEBUG` on test targets | Orch | asserts would otherwise compile out under MinSizeRel. |
| 15 | raylib built with `CUSTOMIZE_BUILD` + `SUPPORT_FILEFORMAT_JPG` | Agent | Spotify album art is JPEG, and raylib 5.5 leaves JPEG decoding off by default. |
| 16 | `.env.example` keeps your empty `SPOTIFY_CLIENT_SECRET=` line (committed in the Soloist cutover alongside a new `SOLOIST_API_KEY=` placeholder) | Orch | It's your change. The app ignores that key. |
| 17 | `dist/.env` carries the client ID for dev builds | Orch *(autonomous)* | A PKCE client ID is public, not a secret. Before you distribute a folder, decide whether to ship your ID or leave it blank so users fill in their own. |
| 18 | **Spotify Soloist replaces librespot** as the local "this computer" Connect device | User (+ Orch for the details) | It is Spotify's official headless client (Aug 2026; macOS/Windows since Oct 2026) and uses the same engine as the Spotify apps, so it gets no audio-key refusals. You asked for it. Clean cutover: librespot code, the cargo build and the second sign-in are removed. |
| 19 | Soloist is **downloaded at runtime** from `soloist-builds.spotifycdn.com` into `<app>/soloist/`, not bundled | Orch *(autonomous)* | Spotify's docs forbid redistributing Soloist binaries. Builds expire 90 days after their build date (exit code 10), so the app re-downloads when a build is missing, expired, or expires within 7 days. Extraction uses the system `tar` (macOS, Windows 10 1803+, a Linux distribution's `/usr/bin/tar` or `/bin/tar`). Updates unpack into `soloist.new/`, are verified with `--version` and swapped in only if newer; inside the 7-day window the CDN is asked at most once a day (`data/soloist-check`). |
| 20 | Soloist key read from `.env` as `SOLOIST_API_KEY=`; data and cache go to `<app>/data/soloist{,-cache}` with a 100 MB cache cap (the minimum Soloist allows) | Orch *(autonomous)* | Same place as the client ID. The cap keeps the folder small. The key is passed to Soloist only as an argument (Spotify's documented limit) and is never logged. |
| 21 | ~~Blocking pairing screen~~ → **pairing happens in the player**: unpaired, Soloist runs only while another device of the account is online (from the poller or a device list), with one dismissible tip naming that device; it stops after 10 min without one. Found in the device list (polled 2 s for 2 min, then 15 s) → `data/soloist-paired` + `data/device-name`, and it starts at every launch | User | Soloist signs in only when an official Spotify app on the LAN picks it, once; no API can do it. No up-front button, like the mobile apps. The name is saved so a hostname change can't change the Connect identity. A device id without the marker (paired with an older build) also starts Soloist; a restored session ("running" without "waiting for login") writes the marker. Only Log out clears `data/soloist`, the marker and the name. |
| 22 | ~~Skip buttons~~ → no skip flow: the app never nags for the key or pairing. Devices → "Enable playback on this computer" opens the key screen (Back returns) | User | The app is a remote first; local playback appears once possible. |
| 23 | Quit signals (SIGTERM/HUP/INT, Cmd-Q, Ctrl handler on Windows) always run the normal cleanup; child engine processes get a backstop that ends them if the app dies: `PR_SET_PDEATHSIG` on Linux, a pipe watchdog on macOS, the job object on Windows | Orch (council finding) | The council found that a SIGTERM to the GUI left the engine running as an orphan. |
| 24 | `FLAG_WINDOW_ALWAYS_RUN` is set in raylib | Agent | Without it, a minimized window ignores our wake-ups and SIGTERM. Event waiting still keeps it at ~0% CPU. |
| 25 | Build: dead-strip, and compile out unused raylib modules (audio, 3D models, the F12 screenshot/GIF hotkeys, automation, busy-wait, the WinMM 1 ms timer, GIF/QOI/DDS). Binaries are **not** stripped | Orch + PerfReviewer *(autonomous)* | 926 KB → 600 KB. F12 used to write screenshots outside the app folder. Keeping symbols costs ~100 KB but makes crash reports readable. |
| 26 | Album art: the smallest cover ≥ 300 px (else the largest ≥ 64 px). Playback polls use `market=from_token` | Orch *(autonomous)* | 64 px art looked blurry in the ~330 pt slot. `market=from_token` drops the per-track country lists from every poll. |
| 27 | Not fixed: raylib crashes inside `InitWindow` if the app launches while the display is asleep | Orch *(autonomous)* | raylib has no way to check for a monitor before `InitWindow`. Launching with the display asleep is rare. |
| 28 | Git history note: commit `0b7e812` accidentally also contains the deletion of `librespot.c`/`.h`, which the cutover agent had already staged. `0b7e812` and `8c1d561` don't build on their own; `df97069` onward does. History was not rewritten | Orch | Never amend or force-push shared history. |
| 29 | **macOS app bundle** `build/dist/Spotify C Player.app` (id `com.spotifycplayer.app`, 0.1.0, macOS 13+, local-network usage text + `_spotify-connect._tcp` Bonjour key). The app folder is `Contents/Resources` (`plat_app_dir`); elsewhere it stays the exe's folder | User (+ Agent) | Drag to Applications to install, drag to the Trash to remove everything. Soloist is our child, so macOS 15+ asks *our* app for Local Network access, which needs those plist keys. The bundle is assembled by hand in CMake, not with `MACOSX_BUNDLE`, which can only name the bundle after the executable; the binary keeps its CLI name `spotify-c-player`. |
| 30 | Ad-hoc signature with hardened runtime, re-signed only when the binary, plist, icon or seeded `.env` change | Agent *(autonomous)* | No developer ID here. The hardened runtime still spawns the downloaded Soloist, and the system libcurl and frameworks load fine (tested). Runtime writes to `Contents/Resources` make `codesign --verify` report modified contents. That's expected for a local build, and the app still launches. Each re-sign changes the ad-hoc identity, so macOS may ask for Local Network access again after a rebuild. |
| 31 | `.env` seeded **at build time** (`packaging/seed_env.cmake`) with the `SPOTIFY_CLIENT_ID` **and `SOLOIST_API_KEY`** lines of the repo `.env`, owner-only (0600). Never the secret. A rebuild rewrites those two lines only when the repo `.env` changed; every other line, `data/` and `soloist/` are kept | User | You asked for the key in the build. A key pasted in the app survives rebuilds until the repo `.env` changes. Supersedes the configure-time seeding of #7/#17. |
| 32 | Key screen: paste the Soloist key (Cmd/Ctrl+V; shown masked, only the last 4 characters), **Save** writes the `SOLOIST_API_KEY=` line into `<app>/.env` atomically, keeping every other line as it was | User | Users can't easily edit `.env` inside a bundle. With an empty box the button reloads `.env` instead. Paste and Backspace read raylib's key-press queue, because a fast press and release could otherwise be missed. |
| 33 | **No console windows.** macOS: launch the `.app`, whose children (Soloist, `/usr/bin/tar`, the `/bin/sh` watchdog, `/usr/bin/open`) are posix_spawn'd with stdin from `/dev/null` or a pipe and no tty (verified: `ps` shows `??`, no Terminal). Windows (code only, untested): GUI-subsystem exe (`WIN32_EXECUTABLE`, MSVC `/ENTRY:mainCRTStartup`). CLI commands attach to the parent console; children use `CREATE_NO_WINDOW` | User | Everything happens behind the GUI. Trade-off on Windows: `cmd.exe` doesn't wait for a GUI-subsystem exe, so CLI output can show up after the prompt. |
| 34 | The quit Apple event (Dock's Quit, logout, `osascript … quit`) runs the same quit path as SIGTERM; `-psn_*` arguments count as a GUI launch; a read-only app folder shows "Move Spotify C Player to Applications" | Agent *(autonomous)* + review | GLFW handles the quit event inside its event wait without waking the loop, so the app ignored it until the next mouse event. The quit handler replaces AppKit's own; Cmd-Q still goes through the menu. |
| 35 | Known OS writes outside the bundle, not ours: macOS's OpenGL-on-Metal shader cache in `$(getconf DARWIN_USER_CACHE_DIR)/com.spotifycplayer.app` | Agent | The shader cache is managed and purged by the system, and the app can't opt out. Soloist's own CFNetwork caches used to land in `~/Library/Caches/soloist` and `~/Library/HTTPStorages/soloist*`; see #36. |
| 36 | Soloist is spawned with `HOME`, `CFFIXED_USER_HOME` and `TMPDIR` (Win32: `USERPROFILE`, `APPDATA`, `LOCALAPPDATA`, `TEMP`, `TMP`) pointing into `<app>/data/soloist-home` (0700), via `plat_proc_spawn_env` | Review (S1) | Keeps every write inside the app folder. Kept on logout (it's cache). |
| 37 | Device name `Spotify C Player (<short hostname>)` | Review (M6) | Two installs on one account no longer look alike, so pairing detection and Play can't pick the other computer. |
| 38 | Play chain: active device (Play) or this computer (library picks, once paired) → this computer → any available device (transfer with play) → one friendly line. The status line shows one message; red only for real errors | User | A signed-in user pressing Play should hear music, not three joined errors. |
| 39 | Children get their own process group; sign-in errors name the cause (port in use, timeout, denied); the login screen has "Reload .env"; logout/quit signal every worker before joining | Review (L1, L2, L6) | A terminal Ctrl-C reaches only us, so Soloist stops gracefully. |
